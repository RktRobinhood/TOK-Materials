## Connection policy

- Three explicit steps: host offer, joiner return code, host acceptance. Copy/paste is the first proven path. A code carries a random128-bit room identity, role, complete SDP and ten-minute expiry. A checksum catches accidental damage; it is not authentication.
- Candidate gathering is bounded at8 seconds. After the host accepts the answer, connection has30 seconds. The joiner may wait until the original code expires while the host completes the manual return step. A disconnected connection gets15 seconds to return; failure closes it and leaves a useful retry message.
- Incorrect, expired, wrong-step and wrong-room codes are rejected before proceeding. Repeated answer acceptance is refused. Cancel closes the channel/peer and clears listeners. A second unexpected data channel closes the attempt.
- Ordered JSON data messages are capped at16,384 characters, with a bounded outgoing buffer. Invalid/oversized inbound values close the connection. Application protocols must still validate message schema, identity and action sequence.
- No cameras, microphones, external relay, game account, backend deployment, teacher service or save key is introduced.
